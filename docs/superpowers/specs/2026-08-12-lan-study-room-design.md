# 局域网自习室（Study Room）设计说明

## 背景与目标

StudyDesk 现有能力全部是「一个人的学习桌面」。本模块引入**同一局域网内的多人陪伴自习**：
同宿舍、同教室、同图书馆的同学互相看得见彼此在专注，用集体目标和预设加油动作互相激励。

核心约束（用户明确要求）：

1. **可以创建、可以加入**，成员之间能够互动。
2. **不提供任何聊天 / 自由文本互动**，从协议层杜绝广告与骚扰。
3. 不依赖任何服务器、账号、密钥——用户装上就能用，离线可用。

## 为什么选局域网而不是云端

| 方案 | 需要服务器 | 需要账号 | 隐私 | 结论 |
| --- | --- | --- | --- | --- |
| 自建后端 | 是（长期成本） | 是 | 数据出网 | 否 |
| 第三方实时服务（Supabase/Ably…） | 否 | **是（API Key）** | 数据出网 | 否 |
| 公共 WebRTC 信令 | 半 | 否 | 依赖第三方可用性 | 否 |
| **局域网 UDP 发现 + TCP 直连** | **否** | **否** | **不出网** | **采用** |

学生真实场景（宿舍、教室、自习室、图书馆）天然同一 WiFi，局域网方案覆盖了绝大多数「一起自习」的语义，
而且零依赖：只用 Node 内置 `dgram` / `net`，不新增任何 npm 包。

## 反广告设计（硬约束）

不做聊天只是第一步，真正的广告面是**任何用户可控的字符串**。因此：

1. **协议层没有文本消息**。成员之间唯一能发送的互动是 `cheer`，负载只有一个**白名单枚举 id**
   （`fighting` / `clap` / `flower` / …共 8 种），非白名单 id 由房主直接丢弃。
2. **昵称与房间名是仅有的两处自由文本**，两者都经过 `normalizeDisplayText` + `looksLikePromotion`：
   - 归一化：全角转半角、去零宽字符与控制字符、折叠空白（防止 `微 信` / `ｑｑ` 之类绕过）。
   - 关键词：链接、`qq` / `微信` / `vx` / `tg` 等联系方式、`代写` / `刷单` / `兼职` 等推广词。
   - 数字：连续 ≥5 位数字（电话 / QQ 号），或数字占比过半。
   - 长度：昵称 ≤ 12 字，房间名 ≤ 16 字。
3. **房主是唯一权威**。成员上报的任何字段都会在房主侧重新 `sanitize` 后才进入名册再广播，
   客户端不能把未经清洗的内容推给别人。
4. 输入框在 UI 侧用 `validateNickname` 即时给出拒绝理由，让正常用户明白规则，而不是静默替换。

## 架构

```
渲染进程                          主进程
StudyRoomView.vue                 studyRoom/service.ts   ← 唯一权威状态
  └ stores/studyRoom.ts  ⇄ IPC ⇄    ├ studyRoom/discovery.ts  (dgram UDP 发现)
                                    └ studyRoom/protocol.ts    (纯函数编解码 + 清洗)
```

- **主进程持有权威状态**，与番茄钟引擎（`PomodoroEngine`）保持一致的设计。
  主进程能直接读 `stores.stats`（今日专注）、`stores.petCompanion`（猫的形象）、`engine.getState()`（专注状态），
  因此身份与状态**无需渲染层参与**即可上报，渲染层只是镜像。
- **发现**：房主 UDP 绑定 45870 等待 `probe`，收到后**单播**回 `beacon`；访客用临时端口向各网段广播地址发 `probe`。
  这样多个访客同时搜索也不会抢占端口。
- **通信**：TCP 45871（被占用则依次 +1 试 8 个端口），NDJSON（一行一条 JSON）。
- **房间码**：把房主 `IPv4 + 端口` 编成 10 位 Crockford Base32（`ABCDE-FGHJK`），
  用于广播被交换机隔离时手动加入，无需知道 IP。

## 互动玩法（无聊天）

| 玩法 | 说明 |
| --- | --- |
| 座位视图 | 每个成员一只自己的猫；专注中播放「写字」动画，休息 / 空闲播放 idle 动画 |
| 实时状态 | 谁在专注、当前阶段、剩余时间、今日番茄数与专注分钟 |
| 集体目标 | 房主设定目标分钟数，全员在房内的专注时长累加，进度条走满触发全员庆祝 |
| 房内排行 | 按「本次在房内的专注时长」排名，前三名有名次标记 |
| 预设加油 | 8 种固定表情动作，可对全体或指定成员发送；接收方猫头顶冒气泡 + 轻音效 |
| 加油统计 | 每个成员收到的加油次数累计显示 |

节流：同一发送者 3 秒内只允许 1 次 cheer，房主侧强制执行，防止刷屏。

## 数据流

1. 渲染层进入页面 → `study-room:get-state` 拉全量 → 订阅 `study-room:state` 增量镜像。
2. 房主 / 访客的专注状态变化（`PomodoroEngine.onUpdate`）→ 主进程 `service.reportFocus()` →
   房主本地更新或访客发 `focus` 帧 → 房主重算名册 → 广播 `roster` → 各端 `study-room:state`。
3. 在房内的专注秒数由**房主**按上报间隔累加（单次最多计 15 秒，防止客户端伪造大额）。

## 落地文件

| 文件 | 职责 |
| --- | --- |
| `src/main/studyRoom/protocol.ts` | 常量、消息类型、NDJSON 编解码、文本清洗、房间码、广播地址推导（纯函数） |
| `src/main/studyRoom/discovery.ts` | UDP 发现（房主应答 / 访客搜索），socket 工厂可注入以便测试 |
| `src/main/studyRoom/service.ts` | `StudyRoomService`：TCP 房主 / 访客、名册、加油、目标、优雅关闭 |
| `src/renderer/src/stores/studyRoom.ts` | Pinia 镜像 + 本地偏好（昵称 / 音效 / 上次房间名） |
| `src/renderer/src/views/StudyRoomView.vue` | 大厅（创建 / 发现 / 房间码加入）与房间（座位 / 排行 / 加油） |
| `src/renderer/src/components/studyroom/*.vue` | 座位卡片、加油条、房间头部 |
| `test/study-room-protocol.test.ts` | 清洗、房间码、编解码、广播地址 |
| `test/study-room-service.test.ts` | 名册、加油白名单与节流、目标累计、断线 |

## 非目标

- 跨网段 / 公网联机（明确不做，避免变成需要运维的社交产品）
- 文字、语音、图片、文件传输（永久不做，这是反广告的根本保证）
- 好友关系、账号体系、历史排行榜持久化
